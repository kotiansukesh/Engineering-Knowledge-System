# AI Practice Engine

## Progression

**Learn → Explain → Build → Evaluate → Break → Defend → Master**

### Learn
Read the concept and identify the core mechanism.

### Explain
Close the note and explain:
- what problem it solves
- how it works
- when not to use it

### Build
Implement the smallest useful version.

### Evaluate
Measure the property that matters:
- quality
- groundedness
- tool correctness
- latency
- reliability
- security
- cost

### Break
Inject one realistic failure:
- provider timeout
- stale retrieval
- malformed tool arguments
- prompt injection
- duplicate action
- dependency outage
- context overflow

### Defend
Change one constraint and defend the redesign.

### Master
Record evidence and update the note/ADR.

## Promotion Gate

Do not mark a topic complete until you can answer:

1. What is the simplest alternative?
2. Why is it insufficient here?
3. What metric proves the design works?
4. What fails first?
5. What happens during dependency failure?
6. What security boundary matters?
7. What would make you reverse the decision?

## Capstone Loop

Use the engine for:
- RAG
- agent workflows
- model routing
- AI gateway
- evaluation
- observability
- Kubernetes deployment
- enterprise AI architecture

The objective is not more notes. The objective is **measured engineering judgment**.
