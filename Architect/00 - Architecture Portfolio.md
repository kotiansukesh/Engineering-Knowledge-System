# Architecture Portfolio

Build original systems rather than only studying existing ones.

## Portfolio standard

Each project should contain:

1. Problem statement
2. Requirements
3. Capacity estimates
4. NFR/SLO scenarios
5. Context and container diagrams
6. Data model
7. Integration model
8. Failure analysis
9. Security/threat model
10. Cost model
11. ADRs
12. Observability plan
13. Migration/evolution plan
14. Architecture review
15. Evidence and redesign triggers

## Suggested projects

### Enterprise Document Intelligence
RAG, model gateway, retrieval, evaluation, security, observability and cost controls.

### Agentic Customer Support
Routing, specialist agents, tools, memory, human approval, audit and evaluation.

### Enterprise Workflow Platform
Workflow orchestration, workers, events, retries, idempotency, sagas and operational recovery.

### Multi-tenant AI Platform
Tenant isolation, model routing, quotas, cost allocation, RAG, guardrails and audit.

## Definition of done

A project is not complete when the diagram looks good. It is complete when its major decisions have explicit constraints, alternatives, evidence and review triggers.
